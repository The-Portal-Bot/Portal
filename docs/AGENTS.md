## Contributing Guidelines

### PR Process
1. Fork repository
2. Create feature branch from upstream master
3. Make changes with clear commits
4. Submit PR with description
5. Address review feedback

### Commit Messages
- First line < 80 characters
- Describe what changed briefly
- Add detailed explanation if needed

### Code Style
- Run `deno fmt` before committing
- Run `deno lint` to check issues
- Follow existing patterns

## Updating Documentation

### When to Update
- New feature added
- API changed
- Bug fixed that affects behavior
- Dependencies updated

### How to Update
1. Edit relevant `.md` file
2. Preview changes locally
3. Submit PR with documentation changes
4. Update website docs if needed

## Best Practices

1. **Keep it current** - Update docs with code changes
2. **Examples matter** - Show, don't just tell
3. **Link generously** - Cross-reference related docs
4. **Version notes** - Document version-specific info
5. **Accessibility** - Use clear language
